# ADR-0001: Выбор технологического стека и архитектуры ExamRAG

- **Статус:** Принято
- **Дата:** 2026-11-26

## Контекст

ExamRAG — учебный и портфолийный DS/ML-проект для подготовки к коллоквиумам и экзаменам по математике. Основные приоритеты:
1. Сфокусироваться на качестве данных (OCR, парсинг PDF), поиске (RAG) и оценке галлюцинаций, а не на долгой фронтенд-разработке.
2. Обеспечить воспроизводимость и проверяемость экспериментов.
3. Избежать жёсткой привязки к одному облачному провайдеру LLM и одному пользователю.

## Решения

1. **Ядро и UI: пакет `src/examrag/` + Streamlit + FastAPI.**
   - Вся логика ML и работы с данными изолирована в `src/examrag/`.
   - Streamlit используется как быстрый интерактивный интерфейс с нативным рендерингом LaTeX.
   - FastAPI отвечает за API и отдаёт статические/HTML-страницы шаринга. В будущем UI можно заменить на Next.js без переписывания ядра.

2. **Абстракция `LLMClient` и кэш OCR.**
   - Провайдер (`gemini`, `openai_compat`, `ollama`) выбирается в `.env`.
   - На Этапе 1 облачный Gemini Vision и локальная модель (например, Qwen-VL) сравниваются по метрикам качества OCR (CER, корректность формул).
   - Результаты OCR кэшируются по хэшу файла/страницы, чтобы не тратить квоту API повторно.

3. **Локальный поиск: точный поиск (numpy / FAISS `IndexFlatIP`) + BM25 вместо ANN.**
   - Эмбеддинги (`intfloat/multilingual-e5-small` на старте) и BM25 запускаются локально.
   - На объёме пет-проекта (тысячи–десятки тысяч чанков) точный поиск не требует приближённых индексов (ANN) и проще в отладке. Интерфейс `Retriever` позволит при необходимости сменить бэкенд.

4. **Однопользовательский режим (Вариант A) с заделом под расширение и шаринг.**
   - Без регистрации и паролей на старте, но в таблице работ сразу закладывается поле `owner_id` (по умолчанию `"local"`) и версионирование схемы через Alembic.
   - Шаринг строится на токене `secrets.token_urlsafe` и хранит **неизменяемый снимок** результата работы (read-only), без перегенерации при открытии ссылки.

5. **Экспорт PDF через Playwright / headless Chromium.**
   - Тот же HTML с отрендеренным KaTeX, который видит пользователь при просмотре/шаринге, печатается в PDF через браузерный движок. Это исключает проблемы WeasyPrint (нет JS/KaTeX) и Pandoc/LaTeX (падения на невалидных фрагментах OCR).

## Последствия

- Быстрый старт и фокус на DS/ML-метриках уже с первых итераций.
- Более тяжёлая зависимость для экспорта PDF (Playwright + Chromium), но единый и предсказуемый рендер формул.
- Лёгкая миграция на многопользовательский режим или другого LLM-провайдера в будущем.
